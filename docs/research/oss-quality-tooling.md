# Code-quality tooling in comparable open-source projects

Question: which linters, coverage services, dead-code tools, scanners and CI gates do well-maintained Go + TypeScript products and self-hosted deploy/infra platforms run, and what is NebulaCtrl missing?

Primary sources only: each project's `.github/workflows/*`, golangci, Codecov, Sonar, knip/Biome/eslint configs and Makefiles, read at the pinned commit shown in the table (the project name links to the tree). `file#Lx-Ly` links point at that commit. NebulaCtrl is read at `8d4a4bd`. Anything not read from a primary file says **unverified**; estimates are marked as such. No build, lint or test was run for this note. Surveyed 2026-11-01. "none found" means no matching workflow or config in the fetched tree, not proof that the project never uses the tool elsewhere (a GitHub default CodeQL setup, for example, leaves no workflow file).

Notes on the sample: pocketbase/pocketbase and minio/minio are archived upstream (minio since 2026-04, still included for its CI); pocketbase has a single release workflow, so it is not in the table. Portainer keeps no `.github/workflows` directory, so only its configs are read. Coolify (PHP) has no test or lint workflow.

## Patterns

Thirteen of the 16 have a golangci config (the other three are TypeScript or PHP). Percentages below are of those 13 unless noted.

**Most do**
- **Go linters beyond `go vet`, curated by subtraction.** Typically 15 to 40 explicit linters. The near-universal ones: unconvert 12/13, misspell 10/13, gocritic 10/13, modernize 9/13, revive 9/13, bodyclose 8/13, bidichk 8/13, durationcheck 8/13, depguard 8/13, usetesting 7/13, errorlint 7/13, testifylint 6/13. Traefik and Mattermost start from `default: all` and switch off the style linters as "too strict" (mnd, lll, nlreturn, gocognit, nestif, ireturn, exhaustruct).
- **Coverage is informational or absent.** 11 of 16 have no coverage service at all (some produce a profile and never upload it). Codecov: Mattermost, Argo CD, Woodpecker (and supabase/pg-meta on v3). Only Argo CD gates (project threshold 2%, patch status off, `fail_ci_if_error: true`); Mattermost is `informational: true`, Woodpecker has `failure: ignore`, supabase's Coveralls step is `continue-on-error`.
- **Generated output and `go.mod` must be committed in sync.** Run the generator, then `git diff --exit-code`: Gitea, Traefik, Prometheus, Nomad, Coder, Argo CD, plus `go mod tidy -diff` and `go fix -diff ./...` in cli/cli.
- **Race detector in CI**: Gitea (DB tests), Caddy, Coder (own job), Argo CD (own job), MinIO, Woodpecker (Makefile), Mattermost (nightly), Nomad (Makefile flag), Prometheus (selected packages).
- **eslint for TypeScript** (10 of the 12 TS-bearing projects). Biome only in Coder and Dokploy.
- **Workflow security**: zizmor (Prometheus, Gitea, Coder, Argo CD, supabase), actionlint (Grafana, Gitea, Nomad, Coder, Argo CD), CodeQL workflow files (Traefik, Prometheus, Mattermost, Coder, cli/cli, Argo CD), Scorecard (Caddy, Prometheus, Mattermost, Coder, Argo CD), govulncheck (Grafana, Gitea, Caddy, Prometheus, cli/cli, MinIO).

**Only a few do**
- shellcheck on repo scripts: Gitea, Coder, Traefik, Argo CD (a job named "Lint shell scripts"), Nomad (`checkscripts` target; whether CI calls it is unverified) (MinIO switched it off "for now"; Caddy and Woodpecker only in pre-commit).
- Spelling gates beyond the golangci linter: typos CLI (Coder, MinIO), misspell (Traefik, Nomad, supabase), cspell (Woodpecker).
- Fuzzing in CI: Prometheus (`fuzzing.yml` called from `ci.yml`, 4 min per target group), Woodpecker (`make fuzz`, 30 s per target by default). - Knip: Grafana (two passes) and supabase (studio only). **None runs `golang.org/x/tools/cmd/deadcode`, ts-prune or unimported**; NebulaCtrl's deadcode gate has no peer in this sample. Dead Go code is otherwise left to staticcheck `unused`.
- Quality platforms: SonarCloud only in Argo CD (with Codecov and a weekly Snyk report). No DeepSource, Codacy or Code Climate config anywhere (no `.deepsource.toml`/`.codacy*` in any tree).
- Image/dependency scanners: Trivy (Woodpecker), OSV-scanner (Coder, on the image), Semgrep (Nomad, own rules), dependency-review (Caddy, MinIO), Snyk (Argo CD). Nobody besides NebulaCtrl combines govulncheck, osv-scanner, Grype and dependency-review.
- Bundle size: Grafana only (fails when a PR adds more than 51200 bytes). Gitea only prints binary sizes.
- Ratchets for new code only: Coder (`--new-from-merge-base` with a second, stricter golangci config), supabase (eslint rule ratchet baselines).
- Flaky-test detection on PRs: Coder re-runs the changed tests 35 times shuffled; Mattermost analyses test results; Nomad notifies on CI failures.
- API/compat gates: Nomad and Prometheus `buf breaking`, Grafana levitate, Woodpecker a breaking-migrations script. No oasdiff or openapi-diff step appears in the fetched workflows.
- hadolint: Woodpecker, in pre-commit only. editorconfig-checker: Gitea, Woodpecker. commitlint-style PR title check: Argo CD only.
- Runner hardening (step-security/harden-runner, audit mode): Caddy, Coder, Argo CD.
- Spam/AI-slop PR filters: Coolify (anti-slop), Woodpecker (agentscan), cli/cli (spam-detection scripts under `.github/workflows/scripts`).

## Where NebulaCtrl already matches or leads

Checked against `.github/workflows/ci.yml`, `security.yml`, `scorecard.yml`, `.golangci.yml`, `knip.json`, `codecov.yml` at `8d4a4bd`.
- Codecov informational with `after_n_builds`, `carryforward`, OIDC upload: the Mattermost pattern. Keep.
- gosec is on in only 3/13 projects (Grafana, Caddy, Coder), nilerr 2/13, unparam 4/13, errorlint 7/13, bodyclose 8/13. NebulaCtrl's six extras are not common practice.
- deadcode (two passes, with test-support packages) and knip: no peer runs the first; knip only two peers.
- actionlint + zizmor in a script, SHA-pinned actions, Dependabot with cooldown, Scorecard, govulncheck, osv-scanner over `bun.lock`, Grype on the image, dependency-review: the whole set exists in no single surveyed project.
- CodeQL runs through GitHub's default code scanning setup (actions, Go, JavaScript/TypeScript), not a workflow file, so the repo has no CodeQL workflow; 6 of 16 surveyed projects run CodeQL from a workflow instead.

## Gaps for NebulaCtrl

Recommendations assume a solo maintainer: cost is CI minutes plus the one-off cleanup and the ongoing false-positive tax.

### 1. Generated-code, `go mod tidy` and `go fix` drift check: adopt
- **Who:** Gitea (`tidy-check`, `swagger-check`, `svg-check`), Traefik (`validate-generate`), Prometheus (`git diff --exit-code` after proto/parser/mixin generation), Nomad (`make check`), Coder (`check_unstaged.sh` four times), Argo CD (tidy and codegen diff), cli/cli (`go mod tidy -diff`, `go fix -diff ./...`), Mattermost (`go fix -diff`).
- **Catches:** a PR that edits a SQL query, a handler or an OpenAPI annotation and forgets `make generate`: stale sqlc output, `openapi/openapi.json`, `apps/web/src/api/gen`, `internal/apiclient`, `docs/reference/cli.md`. Stale clients are exactly the control-plane/agent/web version skew this product cares about. `go mod tidy -diff` catches untidy `go.mod`; `go fix -diff ./...` flags code a newer Go can modernise (go.mod says 1.27.3).
- **Gap in this repo:** no `git diff --exit-code`, `go mod tidy` or `go fix` anywhere in `.github`, `scripts` or the Makefile (grep at `8d4a4bd`).
- **Cost:** one job (est. a few minutes, unmeasured): needs `sqlc` and Bun in CI (`make generate` calls a bare `sqlc`; install it or switch to `go run`), then `git diff --exit-code`. Risk: generator output that is not byte-stable (timestamps, map order); run it twice locally first.
- **Recommendation: adopt.** Highest value per line of YAML, and it protects the solo maintainer from forgetting a step.

### 2. `-race` in CI: adopt, as a nightly job
- **Who:** Gitea, Caddy, Coder, Argo CD, MinIO, Woodpecker, Nomad, Prometheus (subset); Mattermost runs it **nightly** ([workflow](https://github.com/mattermost/mattermost/blob/2b3fb21fe/.github/workflows/server-ci-nightly-race.yml)) rather than per PR.
- **Catches:** data races in concurrent code such as the agent's proxy manager and mesh and the control plane's River workers. `go test` without `-race` cannot see them; `grep -rn -- -race` in the repo, workflows and `tests/run.sh` finds nothing.
- **Cost:** race-enabled runs are slower and use more memory (commonly cited as 2 to 10x; not measured here), so keep it off the PR path. Add a `schedule` job to `full.yml` (or a fourth `go` shard with `-race`) and run `go test -race` over the unit packages; the Docker-backed `integration` tier can stay race-free. First run will likely surface real findings to triage.
- **Recommendation: adopt (nightly + workflow_dispatch).**

### 3. golangci-lint additions: adopt batch A, maybe batch B, skip the rest
Config today: `standard` + bodyclose, errorlint, gocritic (diagnostic tags only), gosec, nilerr, unparam, gofmt.
- **Batch A, adopt** (all common, low noise, bug-finding): `misspell` (10/13), `unconvert` (12/13), `durationcheck` (8/13; `time.Duration * time.Duration` mistakes in timeouts), `bidichk` (8/13; hidden bidi characters in source), `modernize` (9/13; Go 1.27.3 idioms, pair with `go fix -diff`), `testifylint` (6/13; the repo imports testify in 618 files; Gitea disables `empty`, `go-require`, `require-error` as noisy, copy that), `usetesting` (7/13; `t.TempDir`, `t.Setenv`, `t.Context`: the repo has 3046 `context.Background()` in tests, so set `context-background: false` like [Coder](https://github.com/coder/coder/blob/67e216b3c/.golangci.yaml#L169-L170) or the first run is a 3000-line diff). Cleanup size is unmeasured: no linter was run for this note.
- **Batch B, maybe:** `nolintlint` (4/13; the repo has 87 `//nolint`; `require-explanation: true`, `require-specific: true`, `allow-unused: false` as in Gitea) stops directives from rotting. `govet` with `enable: [nilness, unusedwrite]` (Gitea; Prometheus, Traefik, Mattermost use `enable-all`). `noctx` (Coder, Argo CD; Traefik disables it "too strict"; worth a trial for the agent's HTTP clients). `depguard` (8/13) to keep `internal/agent` from importing server-only packages, if that boundary matters to you (Nomad enforces a similar boundary for its `api` package with `go list` checks in `make check`). `revive` (9/13) with a short explicit rule list as in Gitea (its defaults are style-heavy). `forbidigo` with `time.Sleep` banned in tests (Coder's [new-code config](https://github.com/coder/coder/blob/67e216b3c/.golangci.new-code.yaml); the repo has 93 `time.Sleep` in tests, so only with `--new-from-merge-base`). `exhaustive` (Grafana, Caddy) for deployment-status switches.
- **Skip:** gocyclo, funlen, dupl, wsl, mnd, godot, whitespace, lll, varnamelen. Traefik and Mattermost disable most of these on purpose. `gosec` exclusions in `.golangci.yml` (G101, G104, G115, G602, G117) are in line with Caddy's (G115, G107, G203, G204 excluded).

### 4. shellcheck over the repo's shell scripts: adopt
- **Who:** Gitea (pinned container, [lint-shell](https://github.com/go-gitea/gitea/blob/d3021b69e/Makefile#L335)), Coder (`shellcheck --external-sources`, [Makefile#L835](https://github.com/coder/coder/blob/67e216b3c/Makefile#L835)), Nomad (`checkscripts` target), Traefik (`validate-files`), Argo CD (separate job).
- **Catches:** quoting, word-splitting and unset-variable bugs in 15 tracked `.sh` files, including `deploy/install/install.sh` (what users pipe into a root shell), `uninstall.sh`, `deploy/install/lib/hardening.sh`, `tests/run.sh` and `scripts/release/*.sh`. Today `scripts/release/check-workflows.sh` runs actionlint, which only checks `run:` blocks of workflows (and only when `shellcheck` is on PATH: [INFERENCE] from actionlint's documented behaviour); standalone scripts are not checked.
- **Cost:** one step (`shellcheck $(git ls-files '*.sh')`; ubuntu runners ship shellcheck, unverified here), an hour of fixes plus a handful of `# shellcheck disable=` lines. `shfmt` is optional; skip it.
- **Recommendation: adopt.**

### 5. Dead-code depth: knip `--production` pass: maybe (lean adopt)
- **Who:** Grafana runs knip a second time with `--production --exclude exports,types` ([frontend-lint.yml#L373-L378](https://github.com/grafana/grafana/blob/01f74f769/.github/workflows/frontend-lint.yml#L373-L378)) after a full run; `!`-suffixed patterns mark what counts as production ([knip.config.ts](https://github.com/grafana/grafana/blob/01f74f769/knip.config.ts)). supabase restricts knip to the studio app and emits GitHub annotations (`--reporter github-actions`).
- **Catches:** an export or file used only by tests. NebulaCtrl's own `deadcode.sh` already enforces this for Go ("a test of it only keeps it alive"), but `knip.json` lists `src/**/*.test.{ts,tsx}` as entries, so a test-only TS export passes.
- **Cost:** moderate: every `entry`/`project` pattern in six workspaces needs a `!` production variant, and Grafana's list shows the config grows. Do it for `apps/web` only first.
- **Recommendation: maybe.** Worth an afternoon if dead frontend code accumulates; otherwise leave.

### 6. Nightly fuzzing of the existing fuzz targets: maybe (cheap)
- **Who:** Prometheus ([`fuzzing.yml`](https://github.com/prometheus/prometheus/blob/ef78ff642/.github/workflows/fuzzing.yml), `-fuzztime=4m`), Woodpecker (`make fuzz`, 30 s). 
- **Catches:** panics and non-termination in parsers fed untrusted text. The repo has 4 targets (`FuzzParseResolveValidate`, `FuzzSecretScan`, `FuzzParse` in varexpr, `FuzzCheckUpstream`); today `go test` only replays their seed corpus.
- **Cost:** one scheduled job, e.g. 60 s per target (`go test -fuzz` takes one target and one package per call, so loop like Woodpecker's Makefile). Commit any failing input under `testdata/fuzz`.
- **Recommendation: maybe.** Cheap and fits the four parsers that take user input (project config, variable expressions, secret scan, upstream check).

### 7. Spelling beyond the linter: maybe
- **Who:** Coder ([typos](https://github.com/coder/coder/blob/67e216b3c/.github/workflows/ci.yaml#L373) with a `typos.toml`), MinIO (`crate-ci/typos`), supabase (reviewdog misspell), Woodpecker (cspell).
- **Catches:** typos in docs, the marketing site and UI strings, which `misspell` in golangci does not reach (it only sees Go).
- **Cost:** one step; a `_typos.toml` allowlist for product names and domain words (Traefik, Nebula, SSE, sqlc) takes a few rounds.
- **Recommendation: maybe.** Take the `misspell` linter from batch A first; add `typos` only if docs/site typos keep slipping through.

### 8. Licence policy in dependency-review: maybe (no peer evidence)
- **Who:** no fetched workflow sets `allow-licenses`/`deny-licenses` on dependency-review (grep over all surveyed workflows). Gitea generates a `go-licenses` file; cli/cli runs `make licenses-check`.
- **Catches:** a new dependency under a licence that cannot ship inside an AGPL-3.0 product.
- **Cost:** one line in the existing `dependency-review-action` step, but SPDX expressions on dual-licensed packages produce false positives.
- **Recommendation: maybe.** The reason is the AGPL, not peer practice.
