# NebulaCtrl site

The public marketing page, `/compare` and `/faq`, the docs, `llms.txt` and the installer, as a static site. Vite, React 19 and Tailwind 4, prerendered at build time: every route is real HTML that works without JavaScript. Only the interactive islands hydrate: the copy button, the menu, the agent console, the deployment bench, the hero's Eclipse, the 404 digits, docs search and API reference rows. The scroll reveal of the dithered bars is plain CSS and about 90 lines of DOM script (`src/enhance.ts`), no React.

```sh
bun install                                   # from the repository root: one bun workspace
bun run dev                                   # http://localhost:5174 (SITE_URL defaults to that)
SITE_URL=https://nebulactrl.example bun run build   # writes dist/
bun run preview                               # serves dist like a static host (port 4174)
bun run test                                  # make test runs it too
```

| Variable | Meaning |
|---|---|
| `SITE_URL` | Required for `build`: the public origin. It is used in canonical links, the sitemap, `llms.txt` and the install command. |
| `GITHUB_URL` | Optional. The repository URL, `https://github.com/nebulactrl/nebulactrl`; the release workflow sets it. Unset, every GitHub link is hidden, none is dead. The release feed links each release page under it. |
| `SITE_VERSION` | Optional. The release version for the version chip (`v0.1.0`). The build falls back to the latest `v*` git tag; with neither, the chip is not drawn. |
| `GITHUB_STARS` | Optional. The star count shown in the nav next to GitHub, set by the build (the site never asks another origin at run time). Shown only when `GITHUB_URL` is set. |
| `NEBULACTRL_INSTALL_SH` | Optional path to a pre-assembled installer for a build host without Go. |

What is built: `index.html`, `docs/**` (pages, `.md` per page), `llms.txt`, `llms-full.txt`, `install.sh`, `search.json`, `api/v1/openapi.json`, `sitemap.xml`, `robots.txt`, `404.html`, `privacy`, `licence`.

- **Docs** come from the same `docs/**` source and the same pipeline as the in-app docs: `packages/docs` (`buildCorpus`, `buildLlms`, the prose CSS, the API reference view). A broken docs link or anchor fails this build as it fails the web build.
- **`/install.sh`** is `installdeploy.Script()` from `deploy/install`, assembled by `go run ./tests/install/assemble`, so Go must be installed at build time. It is the byte for byte output the control plane serves at `GET /install.sh`; `scripts/install.test.ts` checks it.
- **`/releases/latest.json`** and **`/releases/<version>.json`** are the release feed every control plane reads for its update notice: `{version, publishedAt, notesUrl, notes}` (see [Updating NebulaCtrl](../../docs/operations/updating.md#the-feed)). They are **not** part of a normal build, which has no release: the `site` job of `.github/workflows/release.yml` runs `scripts/release-feed.ts` after `bun run build` (the build empties `dist`) with the output of `gh release view v<version> --json body,publishedAt`, then deploys. Try it by hand: `gh release view v0.1.0 --json body,publishedAt > /tmp/release.json && RELEASE_VERSION=0.1.0 bun run scripts/release-feed.ts /tmp/release.json`. `scripts/release-feed.test.ts` covers the generator; `public/_headers` serves the folder as JSON with a five minute cache.
- **The numbered sections** (`src/pages/landing/sections.tsx`): four sections after the dashboard, each opened by the app's `section-head` with its number, an h2, one lead of at most three sentences and a quieter line for the limits and the doc link. 01 is the deployment bench (`deploy-bench`), which replays the recorded run. 02 is the agent and approval replica (`src/components/console/`, the `console` island): an agent in its own MCP client beside NebulaCtrl's approval page ("Approve a production change", the plan's own summary and effects, Decline and Approve change) and the service's card going Building, Deploying, Live. Its story (`story.ts`, plain operations on a `Stage`) plays once, when it is in view and no other story is playing (`src/islands/motion/play-once.ts`); a click on Approve plays the approval at once, and reduced motion shows the end state, which is also the server markup. 03 shows the control plane stopped and started in a terminal (commands and comments only, no printed output, since no recording holds one) with what keeps running and what waits. 04 is six cards of one size (`id="features"`, the nav's anchor), each an engraved well with a compact static replica from `src/components/replicas/panels.tsx` (rollback list, dial out diagram, engines, routes, the status page's dithered uptime bar, the uninstall command), a title and one paragraph with its doc link. Replicas are hidden from assistive tech with one hidden sentence each and hold no figure that a recording, a doc or the code does not back.
- **The hero and the dashboard under it** (`src/pages/landing/hero.tsx`, `product.tsx`, `screen.tsx`): the headline in two tones ("Deploy to servers you own." / "Stay in control."), the subline, the install command with a line linking the script and what the installer changes, Read the docs and How it compares as raised keys. Behind it the Eclipse (`hero-eclipse`, the page's one scene) over a halftone arc that is the fallback. Under it the real capture of the dashboard, whose bottom 14% dissolves through a dither ramp below the service cards.
- **Dither** comes from `packages/dither` (`@nebulactrl/dither`), the kit the app uses, with deep imports only (the interface barrel would pull Base UI into the bundle). Every number the landing page shows comes from the two recordings or the code; the comparison page draws its bars from the comparison matrix. The dither tokens come from `packages/tokens`.
- **Halftone** is light, shared with the app from `packages/tokens/src/halftone.css` (the `--ambient-*` dials, one `::before` stipple layer and its host classes), in the desaturated ink at a fainter strength than the app (`--ambient-strength` 0.16 in `site.css`, held under 8% texture contrast, with `ink-3` at 7:1 or better on the brightest dot, by `src/contrast.test.ts`). Two places carry it: a faint `ht-dawn` on the body of the docs, compare, FAQ and legal pages (`Document`'s `dawn` prop; only the top 200px) and the hero's arc (`ht-hero`, under the Eclipse, which it hands over to once the scene paints). The 404 has its rim. The homepage sections stay on the plain floor. Forced colours hide every layer.
- **ASCII scenes**: the landing hero has the Eclipse (island `hero-eclipse`) and the 404 sits over the Lost signal scene (`src/pages/legal.tsx`, island `lost-signal-scene`), whose dither "404" glitches in short bursts every 3 to 6 seconds (`BlockCode motion="glitch"`, still under reduced motion). Both are hydrate-on-view islands over the shared `ascii-scene` component: the page marks its copy `data-ascii-quiet` and the block the scene frames `data-ascii-panel` inside a `data-ascii-scope`, and each scene imports only its own entry of `@nebulactrl/ascii`, so a page ships one field shader. The island also sets `data-ascii="on"` on the scope once a frame is painted, which is how the hero's arc and the 404's rim stand down. Reduced motion paints one frame, forced colours hide the layer, and the halftone floor is what shows without WebGL2.
- **Recordings** are replayed, never mocked. `src/content/deploy-recording.json` is one deployment of the sample project's `web` service read back from the API, and `src/content/deploy-recording-fail.json` one whose health check never passes. Re-record them before a release; the tests refuse a recording that holds a secret, a private address or a machine name.
- **Keys** are the app's tactile keys: each raised key stands on a 2px travel edge and sinks onto it when pressed (`--key-travel` from `packages/tokens`). The keys you can press in an island (Copy, Deploy web) add a spring press and an animated icon and label swap through one `motion` component, `src/islands/motion/key.tsx` (`LazyMotion` with its features loaded after hydration).
- **Type**: IBM Plex Sans for headlines (600, tracked tight, as `display-1`, `display-2` and `display-title`) and body text, IBM Plex Mono only for real code and the mono labels. Both are self hosted from `@fontsource` (SIL OFL 1.1). The page sits on the app's floor (`--color-void` holds `surface-base`), and the top bar is the app's: opaque, with a hairline.
- **Design**: the tokens are the subset of `apps/web/src/styles.css` in `src/styles/site.css`; the landing page copy keeps to one type scale and one spacing scale and uses no hyphens in prose.
- No cookies, no analytics, nothing requested from another origin. **Hosting:** Cloudflare Workers static assets at nebulactrl.com, configured by `wrangler.jsonc` (assets directory `dist`, 404 page, `drop-trailing-slash` so the served URLs are the canonical ones, custom domains for the apex and `www`) with headers and caching in `public/_headers` (CSP, HSTS, content types, immutable caching of `/assets`; `src/headers.test.ts` keeps the CSP's inline script hash, the file and the pages consistent). It is deployed only by the `site` job of `.github/workflows/release.yml`, which stamps `install.sh` with the release version first. Check a build without deploying: `SITE_URL=https://nebulactrl.com bun run build && npx --yes wrangler@4.154.0 deploy --dry-run` (the version is `WRANGLER_VERSION` in `release.yml`). The owner actions (Cloudflare token, www redirect) are in `CONTRIBUTING.md`, "Releasing".
